What it does on the notebook (RTX 4070 Laptop 8 GB, Windows 11, Python environment C:\p2\.venv, model cache C:\p2\hf_cache):
  part 0  44 closed-book questions, Qwen3-8B (4-bit), greedy
  part 1  untrained baseline on changed standards tables: Qwen3-8B V1; Qwen3-4B-Instruct-2507 V1 and V2 (414 items per variant)
  part 2  supervised QLoRA fine-tuning of Qwen3-4B on other tables (450 rows, 3 epochs, seeds 1, 2, 3), each followed by V2 inference
  part 3  reward-learning PROCEDURE CHECK (150 steps, group 6, reward = checker verdict); no effect is claimed, no adapter is kept
          (before its first step the update path is tried once on a real sequence: forward and backward, no optimizer step;
           log field "preflight_update". A smoke run whose groups all have equal rewards would otherwise never execute it.)
Peak GPU memory in the logs: the one-off loss-path check (full logits of one sequence) has its own fields
  loss_path_check.peak_vram_*, and the reward check's preflight has preflight_update.peak_vram_*; the counters are reset
  after them, so peak_vram_allocated_gb / peak_vram_reserved_gb of a fine-tuning log are those of training (its memory
  test on the longest sequence included) and those of a reward-check log are those of sampling and updating.
Nothing is scored on the notebook. The package holds no gold answers of the test items, no scorer and no verification engine.
train.jsonl holds the gold of the TRAINING tables only (supervised targets and reward); training and test tables share no value.
Full runs refuse to start without P4_COMMIT.txt (first line: 40-hex hash of the pre-registration commit, lower case).
Smoke tests (--limit) are allowed without it. The data files are checked against data/MANIFEST.json before every stage.

Choices made in the scripts that the frozen settings file does not fix (config/p4_config.json belongs to the
pre-registration commit and was NOT changed; these belong in the decisions log before the run):
  - Reward check, sampling: top_k=0 is passed explicitly. transformers 5.22.2 otherwise fills in its default top_k=50
    (generation/configuration_utils.py, _get_default_generation_params), which would not be a sample from the full
    softmax at temperature 1.0 and top_p 1.0. Every log records it (sampling_kwargs).
  - Reward check, advantage: (reward - group mean) / (sample standard deviation with n-1 + 1e-4). Log field std_kind.
  - Fine-tuning, schedule: lr*(step+1)/10 for the first 10 steps (step counted from 0), then lr*(169-step)/159. Log field lr_schedule.
  - Preparation for training: "lean" (explicit freezing and gradient checkpointing; the tied embedding / output matrix stays
    bfloat16) instead of peft.prepare_model_for_kbit_training, which makes a float32 copy of it. The peft helper is the
    fallback of the fine-tuning smoke test only; the reward check always uses lean.
  - Loss: decoder hidden states + LM head on the answer positions only. Checked against the plain full-logits loss on one
    sequence before training; on the real backend the run stops if the two differ (the plain path does not fit into 8 GB).
  - Reward check: update preflight before the first step (see part 3 above).
  - Fine-tuning and reward check (not inference): GPU memory limit, torch.cuda.set_per_process_memory_fraction =
    (memory PyTorch holds after loading + free memory of the card - 0.3 GB) / total, never below 0.78. Log field vram_cap.
  - Inference with an adapter: the adapter is attached with PeftModel.from_pretrained and NOT merged into the 4-bit weights.
